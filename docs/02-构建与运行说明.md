# HideUtil 构建与运行说明（批次一 + 批次二）

> 适用范围：T01 项目基础设施与自身外壳 / T02 数据模型与核心调度 / T03 隐藏动作处理器主体
> 　　　　/ T04 扩展处理器与健壮性监控 / T05 设置界面
> 合规声明：本工具**仅使用用户态（User Mode）公开 API，零驱动、零内核 hook**。不包含任何"隐藏进程"的内核手段。
> 进程挂起使用 `ntdll!NtSuspendProcess/NtResumeProcess`（公开导出、用户态调用），**不静态链接 ntdll**，运行时经 `GetProcAddress` 解析。

## 2. 三个构建目标

| 目标 | 类型 | 子系统 | 权限 | 用途 |
|---|---|---|---|---|
| **HideUtil** | exe | WINDOWS（无控制台） | `requireAdministrator` | **正式交付物**。无窗口、无托盘、无控制台；仅注册全局热键并静默工作；单实例 |
| **hideutil_cli** | exe | CONSOLE | `asInvoker`（不提权） | **自动化验证抓手**。同用户中等完整性进程之间不受 UIPI 限制，可隐藏普通 `notepad` 等目标 |
| **hideutil_tests** | exe | CONSOLE | `asInvoker`（不提权） | 纯逻辑单元测试：JSON 往返、规则匹配、快照存取、热键编解码、配置往返、挂起配对语义、状态机幂等 |

核心逻辑全部编译进静态库 **`hideutil_core`**，三个可执行目标复用同一份实现。新增的 T04/T05 源文件均加入 `hideutil_core`（`src/ui/SettingsWindow.cpp` 一并编入库，便于后续复用）。

## 4. 运行

### 4.1 HideUtil（正式程序）

直接双击或运行 `build/HideUtil.exe`。因清单声明 `requireAdministrator`，会弹 UAC。

- 无可见窗口、无托盘图标、无控制台；
- 读取/生成 `%APPDATA%\HideUtil\config.json`；
- 注册两个全局热键：
  - `Ctrl+Alt+F12` —— 一键隐藏 / 恢复
  - `Ctrl+Alt+F11` —— 打开设置界面
- **单实例**：再次启动时，新实例通过命名事件 `Local\HideUtil_ShowSettings_Event` + `RegisterWindowMessageW` 广播消息 `HWND_BROADCAST`，通知已存在实例打开设置界面，随后自身退出（返回码 0）；
- 支持命令行参数 `--settings`：启动即打开设置界面（若已在运行则唤起已有实例的设置界面）。

### 4.2 hideutil_cli（命令行测试外壳）

```bash
build/hideutil_cli.exe --list               # 列出可见顶层窗口（进程名 / PID / 窗口类 / 标题）
build/hideutil_cli.exe --hide notepad.exe   # 隐藏并静音匹配的所有 notepad 进程
build/hideutil_cli.exe --status             # 打印状态机状态 + 已快照窗口数（含持久化回退）
build/hideutil_cli.exe --restore            # 恢复上次隐藏（跨进程，读取 state.json）
build/hideutil_cli.exe --suspend notepad.exe # [T04] 挂起匹配进程（suspend-only 规则，不隐藏窗口）
build/hideutil_cli.exe --resume             # [T04] 恢复被挂起的进程（--restore 的别名语义）
build/hideutil_cli.exe --settings-dump      # [T05] 打印当前两个热键与全部规则
```

> `--hide` / `--restore` 通过 `%APPDATA%\HideUtil\state.json` 传递快照，因此**跨进程**也能正确恢复。
> 控制台输出以 `SetConsoleOutputCP(CP_UTF8)` + `WideCharToMultiByte` 输出 UTF-8，**中文标题正确显示**（缺陷 A2 修复）。

## 5. 配置文件

默认路径 `%APPDATA%\HideUtil\config.json`（首次运行自动生成，不写注册表）。关键字段：

```jsonc
{
  "version": 1,
  "language": "auto",
  "hotkey": {
    "hideToggle":   { "modifiers": ["CTRL","ALT"], "key": "F12" },
    "openSettings": { "modifiers": ["CTRL","ALT"], "key": "F11" }
  },
  "runtime": { "requireElevation": true, "startHidden": true, "registerAutostart": false, "pollIntervalMs": 1500 },
  "rules": [
    {
      "id": "rule-001", "enabled": true, "name": "示例",
      "match": { "exePath": null, "processName": "notepad.exe", "windowClass": null, "matchMode": "any" },
      "actions": { "hideWindow": true, "hideTrayIcon": true, "muteAudio": true,
                   "suspendProcess": false, "moveToVirtualDesktop": false,
                   "hideFromAltTab": true, "clearJumpList": false },
      "restore": { "restoreWindowPosition": true, "restoreForegroundWindow": true }
    }
  ]
}
```

- `language`：界面语言，`auto` 跟随系统 UI 语言，或强制 `en-US` / `zh-CN`（详见文末「国际化」一节）。
- `matchMode`：`any`（任一字段命中即适用）/ `all`（全部满足才适用）。
- `key` 支持 `F1`–`F24`、`A`–`Z`、`0`–`9`、`SPACE`/`TAB`/`ESC` 等，或 `VK_0x7B` 形式。
- **`hotkey.openSettings` 现已完整支持保存 / 加载往返**（缺陷修复项 C4，含单元测试）。
- JSON 由内置的 `core/Json` 解析（**零第三方依赖**，约 400 行，含 `\uXXXX` 与代理对）。

### 5.1 各动作对应的数据模型（批次二）

- `suspendProcess` → `TargetSet.suspendPids` / `ProcessSnapshot.wasSuspended`：进 `HideAll` 时挂起，出 `RestoreAll` 时**仅对 `wasSuspended == TRUE` 的进程**恢复，避免误恢复用户本已挂起的进程。
- `moveToVirtualDesktop` → `WindowSnapshot.movedToDesktop` / `prevDesktopId`：移到"非当前"的某个已存在桌面，恢复时移回原桌面；**仅一个虚拟桌面时返回 false（不做任何操作）**。
- `clearJumpList` → 顶层 `GlobalSnapshot.jumpListPids`：按应用 AppUserModelID 调 `IApplicationDestinations::RemoveDestination`；**不清空全局"最近文档"**（不使用 `SHAddToRecentDocs(SHARD_PATHW,nullptr)`）；不支持时返回 false；默认关闭。
- `hideWindow` / `hideTrayIcon` / `muteAudio` / `hideFromAltTab` → 沿用批次一快照字段。

## 6. 设置界面（T05）

- **触发方式**（三选一，均唤起同一实例的设置窗口）：
  1. 全局热键 `Ctrl+Alt+F11`；
  2. 再次启动 `HideUtil.exe`（单实例信号）；
  3. 启动参数 `--settings`。
- **窗口形态**：原生 Win32，**按需创建、关闭即销毁**（不常驻，减少资源占用）。
- **热键录制**：两行（隐藏/恢复、打开设置），点击进入录制态；过滤纯修饰键（必须含至少一个修饰键 + 一个主键）；`Esc` 取消录制；保存前做冲突检测（同一组合被占用时提示）。
- **规则列表**：`ListView` 展示（名称 / 匹配 / 动作），支持新增 / 编辑 / 删除；弹模态子对话框编辑匹配与动作复选框。
- **保存 / 取消**：保存写回 `config.json` 并**运行时生效**（`HotkeyManager::ReRegister` 重注册热键；失败则回滚到旧组合）；取消丢弃改动。
- **日志回放**：`Logger` 默认关闭。

## 7. 运行前提与限制（务必阅读）

- **UIPI**：非提权进程无法操作高完整性（管理员）目标窗口。正式程序以管理员运行可覆盖绝大多数目标；`hideutil_cli` 为 asInvoker，**仅能操作同/低完整性窗口**（足够自动化验证）。
- **进程挂起**：`NtSuspendProcess` 为**未文档化但长期稳定**的公开导出，用户态调用、无内核代码；挂起/恢复严格配对，绝不恢复用户原本已挂起的进程。
- **托盘图标**：仅 Win10 经典通知区域（`ToolbarWindow32`）尽力而为；**Win11 检测不到 `ToolbarWindow32` 时直接优雅降级返回 `false`，不做任何 hack / 注册表改动**。
- **音频**：WASAPI 会话音量静音；**独占模式 / ASIO 绕过会话音量控制**，对其无效。
- **虚拟桌面**：仅使用公开文档化的 `IVirtualDesktopManager`（**不使用**未公开的 `IVirtualDesktopManagerInternal`）；**单桌面环境返回 false**。
- **跳转列表**：仅按应用粒度清理（`IApplicationDestinations`）；**不触碰全局最近文档**；不支持时返回 false。
- **进程监控**：采用**轮询**（`CreateToolhelp32Snapshot` + 可中断 `WaitForSingleObject`），刻意不引入 WMI（避免额外依赖与线程复杂度）。
- **合规红线**：本工具定位合法"隐私遮挡 / 老板键"；严禁用于规避监控或隐藏恶意行为。**不隐藏进程本身**（仅隐藏窗口 / 静音 / 可选挂起）。

### 8.1 快照语义（重要，勿随意改动）

落盘快照（`state.json`）一经建立即为**权威**，重复隐藏只能**并集合并**、绝不能整体替换：

- 同一 `HWND` 已在快照中 → **原样保留**其全部字段（尤其 `wasVisible`），不重新快照；若窗口被应用自己重新显示，则**用存下来的条目**再次隐藏，仍不改写 `wasVisible`。
- `HWND` 相同但 `pid` 不同 → 判定为句柄被复用，**丢弃陈旧条目**，该窗口按新窗口重新快照。
- 快照中 `HWND` **不在**本轮目标内 → **一律保留**（可能属于其它批次的隐藏目标，删除会导致其永远无法恢复）。
- 唯一可"无条件移除"的依据是窗口已销毁（`IsWindow(hwnd) == FALSE`），**绝不依据"是否在本轮观测集合内"**。

> 违反以上任一条都会重现"窗口被隐藏后永久无法恢复"这一严重缺陷（P1 即由此而来）。相关回归用例见 `tests/core_tests.cpp`。

**恢复与无响应目标（P0 语义，勿随意改动）：**

- 所有对**目标窗口**的跨线程操作必须非阻塞：`SetWindowPos` 一律带 `SWP_ASYNCWINDOWPOS`，`ShowWindow` 一律改用 `ShowWindowAsync`；操作前先用 `SendMessageTimeoutW(WM_NULL, SMTO_ABORTIFHUNG)`（默认 1000ms，`WindowHider::SetProbeTimeoutMs` 可调）探测目标线程是否在泵消息。违反此条会对挂起/卡死的目标（如被系统生命周期挂起的 UWP 窗口 OneNote、被本工具冻结的进程）造成 **UI 线程永久阻塞（HideUtil 卡死）**。
- 恢复（`RestoreAll`）遇到**无响应**窗口：**跳过该窗口、继续恢复其余窗口**，绝不因单个窗口卡住整体；被跳过的条目**保留在落盘快照中**（不删除 `state.json`），供下次恢复重试。恢复挂起进程仍**最先**执行（挂起的线程不泵消息，先恢复进程才有机会恢复窗口）。
- **只有本轮恢复全部成功**（无剩余窗口 / 进程）才会清空内存快照并删除 `state.json`；否则把剩余条目重新落盘。
- 隐藏流程中**挂起进程永远最后执行**（在所有窗口隐藏操作完成之后），否则对已挂起线程的窗口操作永远无法完成。
- HideUtil 启动时若检测到遗留快照（上次崩溃 / 强杀），会**自动执行一次恢复**，把一切恢复原状。

**恢复显示态严格使用 `SetWindowPlacement`（P1 修复）：**

- `WindowHider::RestoreWindow` 的显示态**唯一**由 `SetWindowPlacement` 的 `showCmd` 字段决定（`SW_SHOWNORMAL` / `SW_SHOWMAXIMIZED` / `SW_SHOWMINIMIZED` / `SW_HIDE`），原始 `WINDOWPLACEMENT` 在隐藏时由 `GetWindowPlacement` 捕获。
- 恢复路径**禁止**再发 `ShowWindow(SW_SHOW)` / `ShowWindow(SW_RESTORE)`：这两个调用会把窗口强制拉回"居中默认大小"，覆盖刚还原的位置/大小，并产生居中闪烁——这是问题 1（恢复后位置/大小丢失、最大化丢失）的根因。
- 响应窗口（已通过 liveness 探测）的 `SetWindowPos` 走**同步**（无 `SWP_ASYNCWINDOWPOS`），让 `SWP_FRAMECHANGED` 立即生效；恢复完成后追加 `RedrawWindow(..., RDW_INVALIDATE | RDW_UPDATENOW | RDW_FRAME)` 强制 DWM 重绘，避免问题 2（黑屏/不显示）。
- `!wasVisible` 路径：保留 `ShowWindowAsync(SW_HIDE)`（不显示无所谓异步）；`wasVisible` 路径不再发任何 ShowWindow。

**「恢复时将窗口置顶」开关（新功能）：**

- 配置项 `restore.bringToFront`（位于根级，与 `runtime.*` 同级），默认 `false`——恢复不抢占当前前台窗口。勾选后 `RestoreAll` 会对每个成功恢复的窗口调用 `SetForegroundWindow`（尽力调用，系统可能因前台锁拒绝，静默失败可接受）。
- 设置界面有同名复选框「恢复时将窗口置顶（不勾选则保持当前桌面层级，避免抢占前台）」。
- 改动仅限"恢复后置顶"这一项；不替代 P0 的 liveness 探测 + 跳过保留 + 启动自愈，不修改 HideAll 顺序与两阶段落盘。

**前台归还（P1 回归修复，`bringToFront=false` 时抢占用户窗口）：**

- `SetWindowPlacement` **没有** no-activate 选项（不像 `SetWindowPos` 的 `SWP_NOACTIVATE`、`ShowWindow` 的 `SW_SHOWNOACTIVATE`）：它的 `showCmd`（`SW_SHOWNORMAL` / `SW_SHOWMAXIMIZED`）内部等价于 `ShowWindow`，**必然激活并把窗口带到前台**。所以只跳过 `SetForegroundWindow` 是不够的——`bringToFront=false` 时窗口仍会被 `SetWindowPlacement` 顶到前台，抢走用户正在用的窗口（如 WPS）。
- 修复位置在 `HideOrchestrator::RestoreAll`（**不在** `WindowHider::RestoreWindow` 内逐窗口处理，否则恢复多个窗口会导致前台来回跳动、闪烁）：
  1. 恢复前（`stateStore_.Load()` 之后、进程 resume 之前）记录 `const HWND originalForeground = GetForegroundWindow();`。被隐藏的窗口不可能是前台窗口，因此它一定是"用户当前正在用的窗口"。
  2. **所有**窗口恢复完成后**执行一次**前台归还：`bringRestoredToFront == false` 且 `originalForeground` 仍有效且当前前台已不是它时，调 `SetForegroundWindow(originalForeground)`；失败（前台锁）则兜底 `BringWindowToTop(originalForeground)` 至少修复 z-order。
- 静默失败：前台锁拒绝时不弹窗、不打扰用户。**不要**为此引入 `AttachThreadInput`（有挂起风险）。
- `bringToFront=true` 时跳过归还（用户明确要求恢复后的窗口置顶）。

## 国际化

HideUtil 的界面已支持多语言。设计目标是在保持「单文件可移植」的前提下，保证任何语言环境下用户都不会看到空字符串。

**语言选择**

默认 `auto`，跟随系统 UI 语言（中文类子语言解析为 `zh-CN`，其余解析为 `en-US`）。用户可用 `%APPDATA%\HideUtil\config.json` 中的 `language` 字段覆盖：

| `language` | 效果 |
|---|---|
| `auto`（默认） | 跟随系统 UI 语言；系统语言不在已发布语言内时回落到 `en-US` |
| `en-US` | 强制英文 |
| `zh-CN` | 强制简体中文 |

该字段的 JSON 模式定义见 `resources/config.schema.json`（`language` 为上述三个取值的枚举）。

**语言文档**

语言文档位于 `resources/lang/`，当前发布两种：

| 文件 | 角色 |
|---|---|
| `resources/lang/en-US.json` | 英文 —— **权威键集** |
| `resources/lang/zh-CN.json` | 简体中文 |

构建期以 `RCDATA` 资源嵌入 exe（资源 ID `201` / `202`，定义在 `src/ui/AppResources.h`，由 `resources/HideUtil.rc` 引用）。运行时不从磁盘读取，因此不影响单文件可移植性。

**回退规则（两级）**

| 级别 | 情形 | 结果 |
|---|---|---|
| 语言级 | 目标语言未发布 / 未开发 | 英文（`en-US`） |
| 键级 | 当前语言缺少某个键 | 取英文同键的值 |
| 键级 | 英文中也没有该键 | 返回键名本身（让缺失的翻译在测试中显性暴露，而不是静默留空） |

**维护规则**

- **新增或修改任何界面字符串时，必须在同一次改动中同步更新 `resources/lang/` 下所有语言的文档**，英文为权威键集。
- 键级完备性由单测 `TestLocalizerFallbackAndParity()`（`tests/core_tests.cpp`）强制校验，键集不一致会导致测试失败——请把它当作构建门禁，而不是警告。

**已知取舍**

- 设置界面暂未提供语言下拉框；默认 `auto` 已能满足「跟随系统语言」的需求。
- **CLI 的诊断输出刻意保持英文。** 界面徽标在核心层是无语言属性的英文 token（`fg` / `win` / `tray` / `admin` / `bg`），界面层负责翻译显示，CLI 原样打印。这样脚本与日志解析不会随语言环境漂移。
